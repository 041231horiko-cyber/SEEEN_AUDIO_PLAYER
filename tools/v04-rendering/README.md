# V04 STEP 07.1 — Rendering Optimization

## iPhone診断

- STEP 07.1: https://041231horiko-cyber.github.io/SEEEN_AUDIO_PLAYER_V04_PREVIEW/?fps=1
- STEP 06.2: https://041231horiko-cyber.github.io/SEEEN_AUDIO_PLAYER_V04_PREVIEW/?fps=baseline

両URLは同じ音源・タイムコード・アプリ構成を使います。後者はコミット
`6d95111cda2066283e50b797808983357943b862` のレンダラーをそのまま読み込みます。
同じ端末、画面方向、低電力モード、音源と同じ操作順で、両方を個別に測定してください。
パネルの `Reset` で集計を消去し、閉じた状態で4音源を個別に再生します。
短い遷移を比較するときは、再生・停止・音源切替を同じ順番で複数回繰り返します。
測定後にパネルを開き、`Copy report` でテキストをコピーします。

集計は音源と操作区分で分かれ、再生中はノック波数でも分かれます。
フレーム間隔は可視状態で描画したフレームの開始から次の開始までです。
非表示期間と操作区分をまたぐ間隔は集計しません。
平均FPSは集計したフレーム間隔の平均の逆数です。停止を含む壁時計時間のFPSは測りません。
各区分は直近2,048サンプルを保持し、描画時間はJSからCanvas命令を発行するまでを含みます。
ブラウザによる描画の完了時刻やGPUの実行時間は取得していません。
集計や表示の更新は1.5秒ごとで、計測中はパネルを閉じると集計表示の負荷を減らせます。

## 再現手順

Node.js、Playwright、Chromiumを用意し、リポジトリ直下で実行します。
Chromiumの場所が標準のものと異なるときは `CHROMIUM` を設定します。

```sh
node tools/v04-rendering/benchmark.js
node tools/v04-rendering/verify.js
node tools/v04-rendering/verify-browser.js
```

ベンチマークの比較対象は既定でSTEP 06.2のGitコミットと作業ツリーです。
同じChromiumで、描画命令を空関数に置き換えた場合と、DPR 2のCanvas2Dで
1ピクセルの読み戻しまで行った場合をそれぞれ計測し、JSON Linesで出力します。
各定常描画ケースは30回のウォームアップ後に90回測定します。
主旋律、ノック1波、ノック2波とMAX合成、NARROWの反射、Canvas命令の再生は独立したループで
計測するため、内訳を足して定常描画時間に換算することはできません。
開始・停止は既存のアニメーションに60Hz相当の時刻を与えます。停止時は直前のフル描画を各実行の先頭で準備します。
メモリの出力はJSソース上の明示的な確保数と固定テーブルのバイト数です。ヒープ全体やGC停止時間は計測対象外です。
