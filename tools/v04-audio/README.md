# SEEEN V04 STEP 01 — 音源解析

## 再現手順

Python 3.10以上、NumPy、SciPy、Matplotlib、FFmpeg（ffmpeg / ffprobe）を使用します。正式アプリとは独立した開発用ツールです。

```sh
python3 tools/v04-audio/analyze.py /path/to/SEEEN_V04_AUDIO_INPUT.zip /path/outside/repo/seeen-step01
python3 -m http.server 3000 --bind 127.0.0.1 --directory /path/outside/repo/seeen-step01
```

出力先は新規ディレクトリを指定します。レビューは `http://127.0.0.1:3000/review.html` を開き、選択音源のSHA-256照合後に試聴します。閲覧するブラウザと同じマシンでローカルサーバーを起動してください。生成データと音源は配布・公開の判断までGit管理外に置きます。

今回の実行環境は Python 3.12.14、NumPy 2.3.5、SciPy 1.17.0、Matplotlib 3.10.8、FFmpeg 7.1.5です。ZIP内のファイル名、バイト数、SHA-256、AAC・48 kHz・ステレオ・124.700秒を照合します。`audio/` に書き出す4本は、添付から取り出した元のバイト列です。

## 検出結果

| 音源 | 直接ノック候補 | 反響候補 | 最初／最後の直接音（秒） |
| --- | ---: | ---: | --- |
| BRIGHT / WIDE | 35 | — | 1.185 / 121.980 |
| BRIGHT / NARROW | 35 | 27 | 1.180 / 121.980 |
| DARK / WIDE | 35 | — | 1.180 / 121.980 |
| DARK / NARROW | 35 | 27 | 1.180 / 121.980 |

検出された35組は4本で対応しました。同じ組の推定時刻の開きは中央値5 ms、最大20 msです。時刻は5 ms間隔で測った立ち上がり推定値です。近い時刻の発音が同一だと確認できる強い証拠ですが、手付けの正解時刻がなく、単独の弱いノックの取りこぼしと推定時刻の誤差は残ります。

解析時だけステレオPCMへデコードし、12 kHzへダウンサンプリングしました。窓長42.7 msの短時間フーリエ変換（STFT）と5 msホップを使用し、6帯域の正のスペクトルフラックス、局所エネルギーの立ち上がり、直前と比較した短時間RMS、BRIGHT/DARKそれぞれのNARROW−WIDE差分の相関を照合しました。各音源のフラックス候補を独立に抽出したうえで、DARK / WIDEのピークから近傍を照合する判定を採用しています。両明暗の差分ステレオ波形の全区間相関は0.9987でした。除外した強い立ち上がりは比較結果とレビューHTMLに残しています。

NARROWは直接音の約0.460〜0.585秒後に両明暗で再現し、同じ時刻のWIDEのフラックスが相対的に小さい立ち上がりを反響候補としました。27件ずつで、対応する残り8件の反響の有無や初期・複数反射は未確定です。WIDEの残響は個別の反響時刻を分類していません。反響候補は親イベントに付け、独立した発音として数えていません。

## 主旋律の推定

同じ明暗のWIDE / NARROWで、各時間と周波数の小さい方の振幅を採用し、時間方向に持続する成分を優先するメディアンマスクと上限処理を使いました。直接音と反響候補の周辺をマスクし、前後のフレームから線形補間してから平滑化しています。補間区間は全サンプルの約9.4%です。WIDE / NARROWは色ごとに同じ推定特徴量を共有します。

補間区間を除いた同じ明暗のステレオ波形相関はBRIGHTで0.865、DARKで0.931でした。音量傾向や帯域・重心の変化を見られます。DARKの750–1,800 Hzと1,800–3,900 Hzは帯域包絡の相関が約0.21と0.06にとどまり、混合音からの中高域推定には限界があります。支配周波数は解析スペクトルの最大ビンで、推定主旋律の音高とは区別します。無音に近いフレームやエネルギーの集中が弱いフレームでは `null` です。和音、残響、分離しきれないノックの影響があるため、基音の系列全体は `null` としました。旋律の音高を同期に使うにはノック混合前のBRIGHT / DARKの旋律ステム、または正解となるMIDI・音高時刻表が必要です。直接音と反響の精度を詰めるにはノック単独ステム（可能ならドライと残響込み）か発音時刻表が有用です。

## JSON v1

- 各トラックのルートに `schemaVersion`、`trackId`、`audioDuration`、`audioSha256`、`audioFile`、`sampleInterval`、`knockEvents`、`melodyFeatures` があります。
- `knockEvents` は時刻順です。`time` は立ち上がり、`fluxPeakTime` はフラックス最大時刻です。秒は音源先頭から。 `strength` はミックスの立ち上がり付近のRMSを音源内の最大候補で正規化した値です。 `confidence` は4本の整合と差分の強さを使った指標で、確率や人による承認を表す値ではありません。反響候補の `relativeFlux` はその直接音のフラックスに対する比です。
- `melodyFeatures` は列ごとの配列です。時刻は配列番号×`sampleInterval`で求めます。`rmsDbfs` は推定音量、`dominantHz` は最大ビン（約23.4 Hz刻み）、`centroidHz` は重心、`bandEnergyDbfs` は帯域別、`changeDbPerFrame` は隣接フレーム間の帯域dB差の平均絶対値です。`interpolatedRanges` は開始を含み終了を含まないフレーム範囲です。

| サンプルレート | 1本分のフレーム数 | フレーム間隔 | 配列部分のサイズ比 |
| --- | ---: | ---: | ---: |
| 15 Hz | 約1,871 | 約66.7 ms | 約0.75倍 |
| 20 Hz（今回） | 2,494 | 50.0 ms | 1.00倍 |
| 30 Hz | 3,741 | 約33.3 ms | 約1.50倍 |

15/30 Hzの容量はフレーム数から見積もった比です。今回のJSONは1本147,085〜153,206バイト、4本合計600,596バイトです。gzipでは1本28,296〜31,493バイトです。20 Hzの特徴量は局所平滑化後の値です。ノック時刻は別配列に保存するため、この間隔で量子化されません。iPhone 7では選択トラックだけを読み込み、旋律は添字と線形補間で取得し、ノックは時刻順の索引を進める構成が候補です。リアルタイムFFTや粒子ごとの時刻検索を伴いません。実機性能は未測定です。

## ループ境界

最後のノックから次周の最初のノックまで約3.9秒です。終端・先頭各100 msの音声RMSは小さく、左右の最大サンプル段差は約1.37×10⁻⁶（フルスケール比）でした。終端に減衰するモード差があり、境界後の0.4〜0.8秒にも小さなモード差が立ち上がります。直接ノックに分類される立ち上がりは境界上に検出されず、前周の反響が次周まで続く証拠は得られていません。

主旋律の推定RMSは、最初／最後のサンプルでBRIGHTが約−66.4／−61.8 dBFS、DARKが−100（測定下限）／−58.6 dBFSです。低レベルの区間ですが、特徴量の端点は一致していません。AACのデコード出力には4本ともコンテナ時刻以降の704サンプルがあり、計測には124.700秒のプレゼンテーション区間を採用しました。同期設計では時刻リセットとシークを区別し、周回時には末尾から先頭へイベント索引を戻します。シークで飛ばしたイベントを一斉に発火させない扱いと、iOSでの境界の聴感確認が必要です。

## 出力と検証

- 4本のトラック別JSONと `knock-events.csv` に全区間の推定時刻を収録します。
- トラック別PNGに波形、スペクトログラム、推定音量、支配周波数と重心を収録します。緑が直接音、橙の点線が反響候補です。音量図の橙帯は補間区間です。
- `comparison.json` は4本の比較・境界・容量、`detector-audit.json` は判定に使った数値を記録します。`transients.png` は全35組のフラックスの局所比較、`loop-boundary.png` はループ境界前後1秒の波形です。
- 生成した `review.html` は照合済みの音源を再生しながら、イベント時刻へのシークと該当行の強調表示ができます。

CloudのChromiumで4本のSHA照合、音源長、シーク、再生位置の進行、ループ時に再生位置が先頭へ戻ること、異なるバイト列の拒否を確認しました。聴感評価とiPhone実機での再生精度は未検証です。
